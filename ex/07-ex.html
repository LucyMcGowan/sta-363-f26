Application exercise 7: Least squares as a prediction model

STA 363 | Meeting 7 | September 16

Six meetings of machinery for judging a model, and no model to judge. Least squares is the first one, and it is the model every method for the rest of the semester is measured against.

Setup

import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
DATA = "https://raw.githubusercontent.com/LucyMcGowan/sta-363-f26/main/data/"

LinearRegression solved for the coefficients that minimize RSS. Do the same arithmetic yourself.

n = len(Boston)

XtX = X_design.T @ X_design

np.linalg.solve(A, b) solves \(\mathbf{A}z = b\) for \(z\), which is what \(\mathbf{A}^{-1}b\) means. It is more accurate than forming the inverse with np.linalg.inv and then multiplying.

Part 3: More predictors

The last of these four adds forty columns of pure noise, unrelated to medv by construction.

rng = np.random.default_rng(363)
noise = pd.DataFrame(
    rng.normal(size=(len(Boston), 40)),
    columns=[f"junk{j}" for j in range(40)],
)
Boston_plus = pd.concat([Boston, noise], axis=1)

sets = [
    ["lstat"],
    ["lstat", "rm"],
    ["lstat", "rm", "ptratio"],
    ["lstat", "rm", "ptratio"] + list(noise.columns),
]

cv = KFold(n_splits=10, shuffle=True, random_state=363)
rows = []
for cols in sets:
    fit_all = LinearRegression().fit(Boston_plus[cols], y)
    train_mse = np.mean((y - fit_all.predict(Boston_plus[cols])) ** 2)
    cv_mse = -cross_val_score(
        LinearRegression(), Boston_plus[cols], y,
        cv=cv, scoring="neg_mean_squared_error"
    ).mean()
    rows.append({"p": len(cols), "train_mse": train_mse, "cv_mse": cv_mse})

  1. What happens to training MSE as predictors are added? Could it ever go the other way?
  2. What happens to cross-validated MSE between the third row and the fourth? The forty added columns carry no signal, so why did training MSE fall at all?
  3. Which of the four models would you deploy, and what number are you basing that on?

Part 4: Leverage and the LOOCV shortcut

In Meeting 5 the leave-one-out shortcut appeared with an unexplained \(h_i\) in it. Here is what \(h_i\) is.

H = X_design @ np.linalg.inv(X_design.T @ X_design) @ X_design.T
h = np.diag(H)
float(h.sum().round(4)), float(h.min().round(4)), float(h.max().round(4))
(2.0, 0.002, 0.0269)
  1. h.sum() comes out to a whole number. Which whole number, and where does it come from?
  2. Find the tract with the largest \(h_i\). What is unusual about its lstat value?
Boston.loc[[int(np.argmax(h))], ["lstat", "medv"]]
Boston["lstat"].describe().round(2)

Now use the shortcut, which claims the leave-one-out error can be read off a single fit.

resid = y - fit.predict(X)
loocv_shortcut = np.mean((resid / (1 - h)) ** 2)

loocv_brute = -cross_val_score(
    LinearRegression(), X, y, cv=LeaveOneOut(), scoring="neg_mean_squared_error"
).mean()

float(round(loocv_shortcut, 6)), float(round(loocv_brute, 6))
(38.890098, 38.890098)
  1. How many models did each of those two lines fit?
  2. The shortcut divides each residual by \(1 - h_i\). Which observations does that inflate the most, and why is inflating them the right thing to do?

Part 5: Least squares against K-nearest neighbors

Same predictors, same folds, two methods.

cols = ["lstat", "rm", "ptratio"]
lin = -cross_val_score(
    LinearRegression(), Boston[cols], y, cv=cv, scoring="neg_mean_squared_error"
).mean()

knn = {}
for k in [1, 3, 5, 10, 25, 50]:
    m = make_pipeline(StandardScaler(), KNeighborsRegressor(n_neighbors=k))
    knn[k] = -cross_val_score(
        m, Boston[cols], y, cv=cv, scoring="neg_mean_squared_error"
    ).mean()

float(round(lin, 2)), {k: round(v, 2) for k, v in knn.items()}
(28.21,

  1. Which method has the lower cross-validated MSE here?
  2. Least squares with three predictors estimates four numbers. The best KNN model estimates none. Say which one is the high-bias method and which is the high-variance method, and whether the winner here is the one you would have predicted.
  3. What would have to be true about \(f\) for least squares to win by a wide margin?
