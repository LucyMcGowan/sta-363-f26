Sensitivity

\[\text{Sensitivity} = \frac{\text{TP}}{{\require{color}\colorbox{#eec8e1}{$\text{TP} + \text{FN}$}}}\]

Every positive there was, found or missed. So sensitivity is the share of true defaulters the classifier caught, and its denominator has nothing to do with how many it flagged.

Specificity

\[\text{Specificity} = \frac{\text{TN}}{\text{TN} + \text{FP}}\]

Specificity

\[\text{Specificity} = \frac{\text{TN}}{{\require{color}\colorbox{#eec8e1}{$\text{TN} + \text{FP}$}}}\]

Every negative there was. Specificity is the share of non-defaulters correctly left alone, and \(1 - \text{specificity}\) is the false positive rate that the ROC curve plots.

Sensitivity and specificity

Sensitivity is TP / P, the fraction of true positives found. On Default at a 0.5 threshold that is \(81/333 = 0.243\).

Specificity is TN / N, the fraction of true negatives correctly cleared: \(1 - 23/9667 = 0.998\).

Which of those two is a credit card company paid to get right?

The rest of the vocabulary

name definition also called
False positive rate FP / N Type I error, 1 minus specificity
True positive rate TP / P power, sensitivity, recall
Positive predictive value TP / P* precision
Negative predictive value TN / N*

ISLP Table 4.7. P and N are the true class counts; P* and N* are the predicted class counts.

The first two divide by what is true. The last two divide by what was predicted.

Precision

\[\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}}\]

Precision

\[\text{Precision} = \frac{\text{TP}}{{\require{color}\colorbox{#eec8e1}{$\text{TP} + \text{FP}$}}}\]

Everyone the classifier flagged, right or wrong. Precision answers a different question from sensitivity: of the people we called, what share actually defaulted. Lowering the threshold raises sensitivity and usually lowers precision.

Precision against recall

On a rare outcome, a ROC curve can look respectable while precision stays low, because the false positive rate divides by a very large number of negatives.

A model flags 500 customers and 60 of them buy. Which of the two curves would you show the client paying for the mailing?

Moving the threshold

Where 0.5 came from

The Bayes classifier assigns to the class with the largest posterior probability, which for two classes means flagging when \(\Pr(Y = \text{Yes} \mid X = x) > 0.5\).

That threshold minimizes the total number of mistakes, counting both kinds the same. Nothing about the fitted model requires it.

ROC and AUC

The ROC curve

Plot the true positive rate against the false positive rate at every threshold at once. The curve describes the fitted model without committing to a cutoff.

Every point on the curve is one confusion matrix. Sliding the threshold slides you along it.

ROC on Default

ISLP Figure 4.8. The ROC curve for a classifier on Default. The dotted diagonal is a classifier with no information, and the ideal curve hugs the top left corner.

Area under the curve

The AUC summarizes the curve in one number. It equals the probability that a randomly chosen positive is ranked above a randomly chosen negative.

  • 1.0: every positive ranked above every negative
  • 0.5: the diagonal, no information
  • On Default, about 0.95

Ranking against labelling

Accuracy asks a model to commit to a label. AUC asks only whether it puts the right people near the top.

Class imbalance

The null classifier

The null classifier predicts the majority class for everyone. Its accuracy is the majority class proportion, and it uses no predictors at all.

On Default that is 96.67%. On Caravan, where 348 of 5,822 customers bought insurance, it is 94.02%.

What the loss is minimizing

The likelihood counts every observation equally, so 5,474 non-buyers outvote 348 buyers. Predicting “no” everywhere is close to optimal for the loss and useless for the task.

Nothing here is a bug. Which part of the setup would you change?

Caravan

from sklearn.model_selection import cross_validate, StratifiedKFold

Caravan = pd.read_csv(DATA + "Caravan.csv")
y_car = (Caravan["Purchase"] == "Yes").astype(int)
X_car = Caravan.drop(columns=["Purchase"])

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=363)
rows = []
for name, weight in [("plain", None), ("balanced", "balanced")]:
    m = make_pipeline(
        StandardScaler(), LogisticRegression(max_iter=5000, class_weight=weight)
    )
    r = cross_validate(m, X_car, y_car, cv=cv,
                       scoring=["accuracy", "roc_auc", "recall", "precision"])
    rows.append({"model": name, **{k[5:]: r[k].mean() for k in r if k.startswith("test_")}})
pd.DataFrame(rows).round(4)
1
All 85 remaining columns are demographic predictors, so dropping the
response leaves the design matrix.
2
class_weight="balanced" reweights each observation by the inverse of its
class frequency, so the 348 buyers count for as much in total as the 5,474 non-buyers.
3
cross_validate returns several scores from one pass over the folds,
keyed as test_accuracy, test_roc_auc and so on.
model accuracy roc_auc recall precision
0 plain 0.9370 0.7313 0.0087 0.0900
1 balanced 0.6991 0.7301 0.6466 0.1213

What changed

  • Accuracy fell from 0.937 to 0.699
  • Recall rose from 0.009 to 0.647
  • AUC stayed at about 0.73

Reweighting moved the decision boundary and left the ranking where it was.

Choosing what to optimize

  • Ranking customers to contact: AUC
  • Screening where a miss is expensive: recall at a fixed precision
  • Balanced classes and equal costs: accuracy is fine

Every model this semester has been tuned against a single number. Choosing that number is a modeling decision.
