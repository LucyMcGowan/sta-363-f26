Ensemble methods

  • A pruned tree is easy to explain, and it finds interactions without you needing to specify them
  • Its accuracy is sometimes not as high as other regression and classification methods
  • It may not be robust (a small change in the data can cause a large change in the tree)

An ensemble method combines many simple models, into a single model. Bagging, random forests, and boosting all combine trees.

Bagging

Variance of a mean

\[\text{Var}(\bar{Z}) = \text{Var}\left(\frac{1}{n}\sum_{i=1}^{n} Z_i\right) = \frac{\sigma^2}{n}\]

Variance of a mean

\[\text{Var}(\bar{Z}) = \text{Var}\left({\require{color}\colorbox{#eec8e1}{$\frac{1}{n}\sum_{i=1}^{n} Z_i$}}\right) = \frac{\sigma^2}{n}\]

\(\bar{Z}\) is the mean of \(n\) independent observations \(Z_1, \dots, Z_n\), each with variance \(\sigma^2\).

Variance of a mean

\[\text{Var}(\bar{Z}) = \text{Var}\left(\frac{1}{n}\sum_{i=1}^{n} Z_i\right) = {\require{color}\colorbox{#eec8e1}{$\frac{\sigma^2}{n}$}}\]

Averaging \(n\) independent observations divides the variance by \(n\). With \(B\) training sets from the population, averaging the \(B\) fitted models \(\hat{f}^1(x), \dots, \hat{f}^B(x)\) would cut their variance the same way.

The bootstrap

Averaging \(B\) models needs \(B\) training sets, and we have one. What can we do?

A bootstrap training set draws \(n\) observations at random, with replacement (some observations may appear more than once), from the \(n\) observations in the training set.

Bagging

\[\hat{f}_{\text{bag}}(x) = \frac{1}{B}\sum_{b=1}^{B}\hat{f}^{*b}(x)\]

Bagging

\[\hat{f}_{\text{bag}}(x) = \frac{1}{B}\sum_{b=1}^{B}{\require{color}\colorbox{#eec8e1}{$\hat{f}^{*b}(x)$}}\]

The prediction at \(x\) from the model trained on the \(b\)th bootstrap training set. The star marks a fit to a bootstrap sample.

Bagging

\[\hat{f}_{\text{bag}}(x) = {\require{color}\colorbox{#eec8e1}{$\frac{1}{B}\sum_{b=1}^{B}$}}\hat{f}^{*b}(x)\]

Average the \(B\) predictions. Bagging, short for bootstrap aggregation, works with many methods, and it is used most often with trees.

Bagging trees

  • Regression: grow a tree on each of \(B\) bootstrap training sets and average the predictions
  • Classification: take a majority vote, the most common class among the \(B\) predictions

We typically grow large trees without pruning. Why skip the pruning?

A deep tree has low bias and high variance. Averaging \(B\) of them lowers the variance and keeps the bias low.

Out-of-bag observations

A bootstrap training set draws \(n\) times with replacement from \(n\) observations. About what fraction of the observations does it leave out?

About one third. Each bagged tree is fit to about two thirds of the observations, and the remaining third are its out-of-bag (OOB) observations.

Out-of-bag error

Predict observation \(i\) using only the trees for which it was out of bag. About how many predictions does that give?

  • About \(B/3\), one from each tree that never saw observation \(i\)
  • Average them, or take a majority vote, to get one OOB prediction for observation \(i\)
  • The OOB MSE or error rate over all \(n\) observations estimates the test error

With \(B\) large, the OOB error is close to the LOOCV error, and it comes from a single fit of the bagged model.

Random forests

Correlated trees

Suppose one predictor is much stronger than the rest. Where will most of the bagged trees use it?

In the first split. The bagged trees then look alike, and their predictions are highly correlated. Averaging highly correlated quantities lowers the variance less than averaging uncorrelated ones.

Random forests

A random forest grows trees on bootstrap training sets, as bagging does. Each time a split is considered, a fresh random sample of \(m\) of the \(p\) predictors is drawn as split candidates, and the split may use only one of them. Typically \(m \approx \sqrt{p}\).

On average \((p - m)/p\) of the splits do not consider the strong predictor, so the trees are decorrelated. A random forest with \(m = p\) is bagging.

A data set has 100 observations and 9 predictors. What would a good \(m\) be? What about the 19 Hitters predictors?

Boosting

Boosting

Boosting grows trees sequentially, each one using information from the trees grown before it. It uses the original training set, with no bootstrap sampling.

A bagged tree is built on its own bootstrap training set, independent of the other trees. What could a new boosted tree learn from the trees before it?

Algorithm 8.2

  1. Set \(\hat{f}(x) = 0\) and \(r_i = y_i\) for all \(i\) in the training set
  2. For \(b = 1, \dots, B\): fit a tree \(\hat{f}^b\) with \(d\) splits to the training data \((X, r)\)
  3. Add a shrunken copy to the fit: \(\hat{f}(x) \leftarrow \hat{f}(x) + \lambda\hat{f}^b(x)\)
  4. Update the residuals: \(r_i \leftarrow r_i - \lambda\hat{f}^b(x_i)\)
  5. After \(B\) rounds, output the boosted model

Each tree is fit to the residuals of the current model, so it focuses on what the model still gets wrong.

Boosted model

\[\hat{f}(x) = \sum_{b=1}^{B}\lambda\hat{f}^b(x)\]

Boosted model

\[\hat{f}(x) = \sum_{b=1}^{B}\lambda{\require{color}\colorbox{#eec8e1}{$\hat{f}^b(x)$}}\]

The \(b\)th tree, with \(d\) splits, fit to the residuals left by the first \(b - 1\) trees. With \(d\) small, each tree is a simple model on its own.

Boosted model

\[\hat{f}(x) = \sum_{b=1}^{B}{\require{color}\colorbox{#eec8e1}{$\lambda$}}\hat{f}^b(x)\]

The shrinkage parameter, a small positive number such as 0.01 or 0.001. Each tree enters the fit at a fraction of its size, so the model learns slowly.

Boosted model

\[\hat{f}(x) = {\require{color}\colorbox{#eec8e1}{$\sum_{b=1}^{B}$}}\lambda\hat{f}^b(x)\]

Add up the \(B\) shrunken trees. Bagging averages trees grown independently, and boosting adds trees that each depend on the ones before.

Boosting by hand

lam, B, d = 0.01, 1000, 1
r = y.to_numpy().copy()
trees = []
for b in range(B):
    tree_b = DecisionTreeRegressor(max_leaf_nodes=d + 1, random_state=363).fit(X, r)
    r = r - lam * tree_b.predict(X)
    trees.append(tree_b)
f_hat = sum(lam * t.predict(X) for t in trees)
round(float(np.mean((y - f_hat) ** 2)), 4), round(float(np.mean(r ** 2)), 4)
1
lam is the shrinkage \(\lambda = 0.01\), B is the number of trees, and d
is the number of splits in each tree. With d = 1 each tree is a stump, a tree with a single split.
2
The fit starts at \(\hat{f}(x) = 0\), so the residuals r start as the log
salaries in y. .to_numpy().copy() makes r a separate array, so updating it leaves y alone.
3
DecisionTreeRegressor(max_leaf_nodes=d + 1) grows a tree with \(d + 1\)
leaves, which takes \(d\) splits. It is fit to the current residuals r instead of to y, and assigned to tree_b, the \(\hat{f}^b\) of the algorithm.
4
lam * tree_b.predict(X) is the shrunken tree \(\lambda\hat{f}^b(x_i)\) at
every player. Subtracting it from r updates the residuals, and trees.append(tree_b) keeps the tree for the final sum.
5
f_hat adds the \(B\) shrunken trees, the boosted model. The two numbers
printed are the training MSE of f_hat and the mean squared residual, which agree because r is y - f_hat at the end of the loop. 
(0.1271, 0.1271)

Tuning parameters

bagging random forest boosting
\(B\), n_estimators large enough to settle large enough to settle chosen by CV
\(m\), max_features all \(p\), None about \(\sqrt{p}\), "sqrt" all \(p\)
tree size deep, not pruned deep, not pruned \(d\) splits, max_leaf_nodes \(= d + 1\)
\(\lambda\), learning_rate none none 0.01 or 0.001

Bagging and random forests do not overfit as \(B\) grows. Why can boosting?

Each new boosted tree is fit to what is left of the training residuals, so with enough trees boosting can overfit, although slowly. A very small \(\lambda\) needs a very large \(B\).

Interaction depth

ISLP Figure 8.11. Test error for boosting with \(\lambda = 0.01\) and for a random forest with \(m = \sqrt{p}\), predicting cancer against normal from 500 genes. A single tree has a test error of 24%.

With \(d = 1\) each tree is a stump, and the boosted model is additive. In general \(d\) is the interaction depth, since \(d\) splits involve at most \(d\) predictors.

Variable importance

Variable importance

ISLP Figure 8.9. Variable importance for a random forest on the Heart data, as the mean decrease in Gini index relative to the largest.

A forest of 500 trees cannot be drawn as one tree. How can we tell which predictors it relies on?

For regression trees, the variable importance of \(X_j\) is the total decrease in RSS from splits on \(X_j\), averaged over the \(B\) trees. For classification trees, use the decrease in the Gini index.

feature_importances_

importance = pd.Series(rf.feature_importances_, index=X.columns)
fig, ax = plt.subplots(figsize=(7.2, 2.9))
importance.nlargest(10).sort_values().plot.barh(ax=ax, color="#d5008f")
ax.set_xlabel("share of the decrease in RSS")
plt.show()
1
rf.feature_importances_ takes the decrease in RSS from splits on each predictor within each tree, scales each tree’s values to add up to 1, and averages them over the 500 trees. pd.Series labels each value with its column name from X.columns.
2
.nlargest(10) keeps the ten predictors with the largest importance, and .sort_values() orders them from smallest to largest so the largest bar lands at the top. .plot.barh draws horizontal bars so the names stay readable.

Compare with the first splits. Would CAtBat get a larger or smaller share for bag? Why?

Tree ensembles

each tree is grown on the trees are grown predictions are combined by
bagging a bootstrap sample independently, all \(p\) predictors per split averaging, or a vote
random forest a bootstrap sample independently, \(m\) random predictors per split averaging, or a vote
boosting the original data in sequence, each fit to the residuals adding shrunken trees

All three give up the single tree we could draw in exchange for more accurate predictions, and variable importance summarizes what the ensemble relies on.
