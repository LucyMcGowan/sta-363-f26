Data leakage

Anything estimated from the data is part of the model, and must be learned on the training fold alone.

  • Centering and scaling
  • Imputing missing values
  • Choosing which predictors to keep
  • Deciding how to bin or encode a variable

Leakage from selection

Simulated noise

n, p = 100, 2000
X = rng.normal(size=(n, p))
y = rng.integers(0, 2, size=n)
1
n is 100 rows and p is 2000 predictor columns, an unusually
wide data set on purpose.
2
rng.normal(size=(n, p)) draws a 100 by 2000 array of standard normal
noise, assigned to X; none of these columns are constructed to relate to y.
3
rng.integers(0, 2, size=n) draws 100 values from {0, 1}, a random two
class label with no relationship to any column of X.

There is no true signal here. What accuracy should any honest method report?

Selection outside the loop

from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import cross_val_score, StratifiedKFold

keep = SelectKBest(f_classif, k=20).fit(X, y).get_support()
X_kept = X[:, keep]

cv = StratifiedKFold(5, shuffle=True, random_state=363)
leaky = cross_val_score(KNeighborsClassifier(5), X_kept, y, cv=cv)
float(leaky.mean().round(3))
1
SelectKBest ranks predictors by a scoring function and keeps the top
k; f_classif is the ANOVA F-statistic between each column of X and the class label y.
2
SelectKBest(f_classif, k=20).fit(X, y) scores all 2000 columns against
the full y and keeps the top 20; .get_support() returns a boolean mask of which columns were kept, assigned to keep. Fitting on the full X and y before any split is the leak.
3
X[:, keep] uses that boolean mask to select only the 20 chosen
columns, assigned to X_kept.
4
StratifiedKFold(5, shuffle=True, random_state=363) builds 5 folds that
preserve the class proportions of y in each fold.
5
cross_val_score(KNeighborsClassifier(5), X_kept, y, cv=cv)
cross-validates a 5-nearest-neighbors classifier on X_kept, the already-selected columns, so every fold’s “test” data already influenced which columns were chosen. 
0.85

We cross-validated. Why is this not 0.5?

Selection inside the loop

from sklearn.pipeline import Pipeline

pipe = Pipeline([
    ("select", SelectKBest(f_classif, k=20)),
    ("knn", KNeighborsClassifier(5)),
])

honest = cross_val_score(pipe, X, y, cv=cv)
float(honest.mean().round(3))
1
Pipeline takes a list of (name, step) pairs. SelectKBest(f_classif, k=20) is now the "select" step inside the pipeline, so scikit-learn refits it on each training fold alone rather than on the full data.
2
cross_val_score(pipe, X, y, cv=cv) cross-validates the whole pipe
object, so SelectKBest and KNeighborsClassifier(5) are both refit from scratch on each fold’s training rows, exactly like leaky above but with the selection step properly inside the loop. 
0.53

Same data, same method. Only the location of the selection step changed.

Pipelines

Pipeline structure

  • We have used make_pipeline(StandardScaler(), KNeighborsClassifier(25))
  • A pipeline is an ordered list of steps: transformers, then one estimator at the end
  • Calling .fit fits each step and passes its output to the next; .predict runs the same chain
  • Inside cross_val_score or GridSearchCV the whole chain is refit on each training fold
  • So every step that learns from data (scaling, imputing, selecting) stays inside the fold

make_pipeline and Pipeline

from sklearn.pipeline import make_pipeline, Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier

pipe = make_pipeline(StandardScaler(), KNeighborsClassifier(25))
list(pipe.named_steps)
1
make_pipeline and Pipeline both come from sklearn.pipeline, the same
module imported in Meetings 4 and 5.
2
make_pipeline(StandardScaler(), KNeighborsClassifier(25)) builds the
two-step pipeline pipe, scale then classify, the same call written for KNN
3
list(pipe.named_steps) returns the step names make_pipeline assigned
automatically, each lowercased from its class. Pipeline([(name, step), ...]) is the longer form where the names are chosen by hand, as with "select" and "knn" on the previous slide. 
['standardscaler', 'kneighborsclassifier']

prep
1
ColumnTransformer applies a different transformer to a different
subset of columns, then concatenates the results into one array.
2
num lists the four numeric predictor column names that will be
scaled.
3

encoded.
4

5

named in cat, creating a 0/1 indicator column for every category except one (drop="first"), which avoids a redundant, perfectly collinear column.

Missing data

Imputation is estimation. An imputed value is a prediction, and it must be learned on the training fold.

  • Dropping rows discards information and can bias the result
  • Filling with a column mean is a model (a pretty weak one)
  • For prediction, missingness itself may be informative

SimpleImputer

from sklearn.impute import SimpleImputer
from sklearn.neighbors import KNeighborsRegressor

num_steps = Pipeline([
    ("impute", SimpleImputer(strategy="median")),
    ("scale", StandardScaler()),
])

prep = ColumnTransformer([
    ("num", num_steps, num),
    ("cat", OneHotEncoder(drop="first", handle_unknown="ignore"), cat),
])

full = Pipeline([("prep", prep), ("knn", KNeighborsRegressor(5))])
1
SimpleImputer(strategy="median") replaces missing values in a numeric
column with that column’s median, computed only from the training fold it is fit on.
2
("scale", StandardScaler()) runs second, so scaling happens after
imputation fills the gaps, still learned from the training fold alone.
3
OneHotEncoder(drop="first", handle_unknown="ignore") adds
handle_unknown="ignore" so a category value seen in a test fold but never seen while fitting on the training fold produces all zero indicator columns instead of raising an error.
4
full chains the entire prep (imputation, scaling, and encoding) with
KNeighborsRegressor(5) into a single estimator, so calling .fit on full fits every preprocessing step and the model together.

GridSearchCV

from sklearn.model_selection import GridSearchCV, KFold

grid = GridSearchCV(
    full,
    {"knn__n_neighbors": [1, 5, 10, 25, 50]},
    cv=KFold(5, shuffle=True, random_state=363),
    scoring="neg_mean_squared_error",
)
grid.fit(Credit[num + cat], Credit["Balance"])
grid.best_params_
1
GridSearchCV cross-validates the estimator once per combination of
parameter values it is given, and reports the best one.
2
{"knn__n_neighbors": [1, 5, 10, 25, 50]} is the grid of candidate K
values for the "knn" step of full; the double underscore in knn__n_neighbors reaches into that named step’s n_neighbors parameter.
3
cv=KFold(5, shuffle=True, random_state=363) runs 5-fold CV, refitting
full, imputation and scaling included, on each training fold for every candidate K.
4
grid.fit(Credit[num + cat], Credit["Balance"]) runs the full search on
the numeric and categorical predictor columns against the response Credit["Balance"]. 
{'knn__n_neighbors': 5}

The double underscore names a step’s parameter: step__parameter.

Training, validation, and test

Training: fit the model.

Validation, or the CV folds: choose among models.

Test: report how the chosen model does. Once.

CV accuracy 0.88, test accuracy 0.81. Which do you report?

Repeated measures

Repeated measurements on the same subject are correlated with each other, not independent draws. A random split can put one subject’s rows in both the training fold and the test fold.

A nearest-neighbor model can then “recognize” the subject, since its near-duplicate points sit right there in the training data, instead of generalizing to a subject it has never seen.

GroupKFold

GroupKFold folds on the group label, not the row: every row from a given subject goes together in the training set or together in the test set, never split between them.

Pass it a groups array, one label per row, patient_id here. The fold assignment respects that label instead of splitting row by row.

Look-ahead leakage

A predictor recorded after the outcome can look powerful in cross-validation and be useless at prediction time, since it is a consequence of the outcome rather than something known when the prediction is needed.

Leakage checklist

  • Did any step look at the outcome before the split?
  • Is every learned transformation inside the pipeline?
  • Does any predictor record something measured after the outcome?
  • If the data have groups or a time order, does the split respect them?
