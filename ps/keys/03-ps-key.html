Answer key, Problem set 3: Cross-validation and leakage

STA 363 | Instructor copy

1. Bias and variance of CV procedures

(a) From most biased to least biased: validation set approach, k-fold CV with k = 5 or 10, LOOCV. The validation set approach fits its model on only about half of \(n\), so that fit is estimating \(f\) from a much smaller sample than the one that will actually be used, which pushes its test error estimate up. K-fold CV with k = 5 or 10 trains each fold’s model on \((k-1)/k\) of the data, closer to the full sample. LOOCV trains each model on \(n - 1\) observations, essentially the whole data set, so its estimate is almost unbiased for the error of a model fit on all \(n\) points.

(b) Validation set would have the highest variance, technically they can say 5/10-fold cross validation and LOOCV we can’t know for sure which would have lower variance (the book would probably say LOOCV is higher but that isn’t totally true). LOOCV’s \(n\) training sets overlap in \(n - 2\) of their \(n - 1\) points with every other training set, so the \(n\) fitted models, and the \(n\) error terms averaged to form the LOOCV estimate, are highly correlated with each other. Averaging \(n\) highly correlated quantities does not shrink variance the way averaging \(n\) independent quantities does, LOOCV does not automatically have the lowest variance of the three.

(c) The validation set approach is worth choosing when a single fit is expensive to compute and \(n\) is large enough that losing half the data to the held-out set costs little bias, for example a large data set with a model that takes hours to train, where k-fold or LOOCV would multiply that cost by k or by \(n\). It is also the right choice when the model selection step needs one estimate that is not itself built from data that will later be reused for anything else, such as a single clean number to report at the end of a project.

2. LOOCV on Smarket

(a) When cv is an integer k, cross_val_score splits the data into k roughly equal folds, and for each fold in turn it fits the estimator on the other k minus one folds and scores it on the held-out fold, returning the k scores. When cv=LeaveOneOut(), it does the same thing with \(n\) folds of size 1: for each observation in turn, it fits the estimator on the other \(n\) minus one observations and scores the single held-out point, returning \(n\) scores, one per observation.

(d) An error rate of about 0.503, essentially a coin flip, says Lag1 and Lag2 carry almost no signal for predicting Direction. Part 1c argued that LOOCV’s extra computation is worth paying for when the training sets across models are similar but the data is not so redundant that a cheaper procedure already captures everything. Here, because the true relationship is so close to noise, the bias LOOCV saves over 10-fold CV would not translate into a meaningfully different or more useful estimate: both procedures land near 0.50, so the many extra model fits are not buying a more stable or more informative answer in this particular data set.

(c) Across the five splits, the error rate moves around by more, from about 0.025 to about 0.027, just from changing which 30% of customers land in the test set, than adding student ever moves it within a split, where the two columns typically differ by 0.0000 to 0.0003. A single 70/30 split is unreliable here because the test set has only about 300 defaulters times a roughly 3% default rate, on the order of 90 positive cases, so a handful of these customers landing on one side of the split or the other is enough to shift the error rate by more than the effect being tested for.

Cross-validation does not change the answer to part c: averaging over 10 folds instead of looking at 5 separate 70/30 splits removes the split-to-split noise that made a single split unreliable, and once that noise is averaged out, student still shows no meaningful improvement over balance and income alone.

(d) Yes, this can leak information. StandardScaler computes each numeric column’s mean and standard deviation from whatever data it is fit on, and OneHotEncoder learns its category levels the same way. Fitting the ColumnTransformer on the full data before splitting into folds means every fold’s held-out points have already contributed to those means and standard deviations, so information from a fold’s test observations leaks into the transformation applied to that same fold’s training data, and by extension into the model fit on it. The consequence is that each fold’s held out points are not really unseen: the CV error GridSearchCV reports is optimistically biased, too low relative to the error the model would show on genuinely new data, and the chosen n_neighbors is being selected using a metric that does not honestly reflect out of sample performance.

5. Matching CV strategy to structure

(a) StratifiedKFold. The condition is present in only 2% of patients, so plain KFold’s random folds can easily land a fold with very few or even zero positive cases, making that fold’s error rate close to meaningless and destabilizing any model selection based on it. StratifiedKFold keeps the same roughly 2% positive rate in every fold.

(b) GroupKFold, grouped by student. Each student contributes eight correlated rows, since a given student’s homework and exam performance share a common ability level. Plain KFold would routinely put some of a student’s rows in the training fold and the rest of that same student’s rows in the test fold, letting the model learn that particular student’s level during training and then get credit for recognizing it at test time, which overstates how well the model predicts scores for students it has never seen.

(c) GroupKFold that respects time order, training only on days before the ones being predicted. Prices on nearby days are dependent, and the model will only ever be deployed to predict a future day from past days. Plain KFold would let some training folds contain days that come after days in the test fold, so the model could pick up information that would not actually be available at prediction time, inflating its apparent accuracy.

(d) StratifiedKFold. With a 3% default rate, this is the same rare outcome problem as part a: random KFold folds risk containing very few defaulters, while StratifiedKFold keeps the roughly 3% default rate consistent across every fold.
